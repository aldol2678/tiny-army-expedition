# 1.0 구현 기준선 · v10-trial-p0

2026-10-18 UTC. 상태: 설계 정리와 격리된 구현 실험을 시작하는 기준. 밸런스 확정·제품 통합·배포 승인이 아니다. 이 문서는 아래 선택한 시험값에 한해서 이전 문서의 ‘미확정’을 실행 가능한 P0 기본값으로 좁힌다. 사용자 확정과 공학적 시험값은 구분한다. 기존 상세 기술 계약은 그대로 참조한다.

## 1. 사용자 확정 / 해석 / 구현 기본값

사용자 확정:
- 5장, 모든 적법한 경로에서 장당 최소 7전투. 시드 기반 간단한 분기 지도. 불필요한 합류·빈 휴식·대기 화면 제거.
- 3장 유물 수집 → 4장 궁극 진입 → 5장 활용.
- 2차 고유 기술 2개, 3차는 그 2개를 유지하고 궁극 1개 추가. 평타·플레이어 지휘는 별도다.

명시적 해석: 보스를 7전투에 포함한다. P0는 정확히 7×5=35전투로 구현한다. 사용자가 일반전만 7을 뜻했다고 정정하면 생성기 버전을 바꾼다.

공학적 기본값: 아래 모든 금액·보상 횟수·피로·성장 자격·궁극 입력 방식·각성 한도는 조정 가능한 실험이다. 소수 병력, 회복 서비스 0, 특정 유물 0, 궁극 0 경로를 막아서 수치를 정당화하지 않는다. 전투 승률 검증 전 ‘균형 잡힘’ 또는 ‘완주 보장’이라 하지 않는다.

## 2. 지도와 성장 계약

- 장마다 전투층 1~6 + 보스층 7. 폭 2~3, 모든 노드 도달 가능, 전방 간선만. 일반전만 선택할 수 있는 연속 경로를 보장한다. 보스 종류·주요 위험은 장 시작에 공개한다.
- 선택 서비스는 층 2·4 뒤 각각 최대 1회, 총 0~2회/장. 항상 무료 직행 가능. 서비스를 들어가거나 지나치는 것 자체로 XP·회복·보상을 지급하지 않는다. 서비스가 전투층을 대체하지 않는다.
- 전투층별 XP는 3/1/1/1/1/2/1, 장당 10. 출전 상한 XP 0/4/9/13 → 6/7/8/9. 보유 상한 20, 배치 격자 12와 구분한다. 출전 상한 해금은 자동 모집이 아니다.
- 전체 전투 1~34 승리 뒤 결과 패널에서 선택 보상 1회, 35 뒤는 정산만. 보상창·리롤·재접속이 승리나 XP를 다시 처리하지 않는다.
- 전체 전투 2 뒤 진화, 5 뒤 훈련 I, 8 뒤 훈련 II의 적격 성장 기회를 보상 3슬롯 중 1슬롯으로 예약한다. 추가 공짜 보상이 아니다. 각 선택의 골드 비용 0G, 다른 보상 포기가 비용이다. 거절 가능하고, 순서/대상이 맞지 않으면 자동 성장을 주지 않는다.
- 1차 갈래 + 훈련 II를 갖춘 마지막 성장 거래에서 2차 및 두 실제 기술을 동시에 연다. 별도 네 번째 선택·추가 전직비 없음. ID·훈련 교과·컨디션 보존. 이름만 2차로 바꾸지 않는다.
- 3장 보스(전체 21) 보상 중 1슬롯은 미획득 목표 열쇠 또는 비궁극 핵심 유물 선택 기회로 예약한다. 정예·상점 방문 불필요. 거절/이미 보유/미적격은 고정 fallback이며 추가 지급 없음.
- 4장 진입 지도 패널에서 2차 + 해당 열쇠 I 이상 보유자의 명시적 각성 선택. 원정당 최대 1명, 0G, 열쇠 비소비. 거절도 정상 진행. 5장에 뒤늦게 필수화하지 않는다.
- 선택한 첫 가족 외 병과는 미구현 기술을 ‘완성된 2차/3차’로 표시하지 않는다. 첫 슬라이스의 능력 플래그로 지원 범위를 제한한다.

## 3. 경제·제시기 P0

- 시작 0G. 일반/정예/보스 승리 10/20/30G 유지. 모집 20G, 훈련 구매 30G, 유물 희귀도별 10/15/20/30/40G, 제련 I→II 20G·II→III 30G 유지. 상점 진화 상품은 P0에서 추가하지 않는다.
- 목표 열쇠 상점 가격 20G. 3장 전투 2 뒤 상점을 방문할 때만 구매할 수 있으며, 건너뛰면 소급 구매 불가. 보스 목표 슬롯이 별도 대안이다.
- 보상당 3슬롯·최대 1개 선택 또는 패스. 리롤은 5G·보상당 최대 1회. 예약 성장/목표 슬롯은 리롤로 소실되지 않으며 나머지 슬롯만 다시 추첨한다. 같은 보상 예산을 넘지 않는다.
- 일반 슬롯은 모집/성장/유물 1:1:1 카테고리 가중치부터 시험한다. 카테고리 → 기존 0.9 희귀도 함수의 버전 고정 복제 → 적격 ID → 사전 고정 fallback 순서다. 희귀도가 없는 성장/모집에는 희귀도 추첨을 적용하지 않는다. 신규 72종 균등 추첨 금지.
- P0의 적격 후보 없음/중복/포화 fallback은 ‘이 슬롯 패스’(0G·0성장)로 고정한다. 결과가 지나치게 빈약하면 이후 프로필에서 바꾸되, 현재 선택 후에 임의 보상으로 바꾸지 않는다. 편성 변경으로 카테고리·희귀도·보상 전체를 무료 재추첨하지 않는다.
- 첫 검증 풀 25종=기존17+열쇠4+배치4. 72종 목록은 보존하며 조건부11·후속36은 활성 풀에 넣지 않는다. 첫 슬라이스에서 신규8종이 전부 구현되었다고 간주하지 않는다. 미구현 효과는 확률 풀에서 제외하고 기능 테스트용 fixture로만 명시한다.
- 실효 증가·대가·남은 기회·각성 자격을 함께 미리 보여준다. 포화 때문에 효과 없는 제련은 차단. 경제 유물37~40은 제외하므로 불리한 20/30G 제련을 출시하지 않는다.
- 정예0 전체 총수입450G, 최종 보상 전 사용가능420G. 장당정예2면550G/520G. 34회 전부 리롤하면170G 소비. 이는 지갑 산술일 뿐 성장률·구매 기회·필요 병력 보장이 아니다.

## 4. 35전투 피로를 위한 시험값

기존 일반4/정예8/보스10은 무교대·서비스0·전투불능0 조건에서 3장부터 바닥을 만든다. 따라서 P0는 다음 단순한 감소안을 사용한다.

- 출전 병사 승리 소모: 일반1 / 정예2 / 보스3.
- 전투불능 추가4 유지. 승리 시 전투 시작부터 예비였던 병사만 +6, 출전자는 예비 회복 대상 아님. 결산 한 번만 적용.
- 컨디션 범위0~100, 효율0.70+0.003×컨디션 유지. 숨은 장 전환 회복·보스 전 자동 회복·출전 인원에 따른 보정 없음.
- 선택 휴식의 P0 행동은 전체 보유 병사 컨디션+20, 상한100, 0G. 서비스 방문 기회와 다른 선택을 포기한다. 휴식은 선택이며 생성·방문을 필수로 하지 않는다. 유물/특정 지원병/큰 예비대를 필수로 삼지 않는다.
- 항상 같은 병사가 승리하고 전투불능0이면 일반6+보스1의 장당 소모9, 장말91/82/73/64/55. 5장 보스 진입58, 효율87.4%; 최종55는86.5%다. 장당 정예2는 장당11, 최종45(83.5%). 모든6개층 정예면 장당15, 최종25(77.5%).
- 이 산술은 6명 또는 출전9명을 계속 채워도 각 출전 병사의 같은 소모를 설명하며 무료로 12~20명 예비를 확보했다고 가정하지 않는다. 후발 모집자는 참가 횟수대로 계산한다. 전투불능·실제 영입비·전투 패배·역할 부족은 별도 실험에 반드시 포함한다.
- P0 실패 시 피로/조우/성장/시간을 원인별로 조정한다. 강제 휴식이나 특정 유물 지급으로 실패를 숨기지 않는다. 전투 중 정상 치유의 필요성은 ‘서비스 회복0’과 별개다.

## 5. 첫 슬라이스: 창병 한 계열의 두 역할

구현 위치는 별도 army-v10-implementation. 운영 앱·전역 0.9 정의는 수정하지 않는다.

- guardian → 성채수호병: guardian_link + bastion_guard.
- charger → 돌파선봉병: charge + charge_cover.
- 궁극 iron_oath의 수성/돌파 변형. 기존 branch ID와 특화/운용 훈련을 유지한다.
- skill-implementation-contracts.md §§1~3.2,4.1의 P0 타깃·행동 잠금·예산·이벤트 규칙을 사용한다. 공유 행동으로 평타와 신규 기술의 무료 동시 출력을 막고, 최대55% 감소/보호량 예산/컨디션 1회 적용을 검증한다. 돌격은 실제 이동·넉백이 아니다.
- 기본2기술 자동, 궁극은 조건형 자동. 출전 각성 병사 전투당1회, 5초 뒤 armed. 적격 기본 기술 commit과 함께 사용권 소모, CD/마나 초기화 없음. 조건 부재 시 보류, 사망/전투 종료 시 잔여권 폐기. 지휘 1/2 입력 유지. 이것은 공학적 P0 선택이지 사용자 확정 입력안이 아니다.
- 첫 산출물은 순수 지도/성장/거래 상태 모듈 + 결정적 창병 행동 모듈 + 테스트/제한 보고서다. 별도 모듈 테스트 통과는 실제 제품 전투 통합·35전투 완주·UI 완료가 아니다.

## 6. 저장 격리·단계별 검증·중단/복구

1. 격리 P0: profileId=v10-trial-p0, 실험 campaign/map/combat/content 버전을 명시하고 완전한 지원 조합만 허용한다. localStorage가 필요하면 tiny-army-v10-trial-p0만 사용한다. 제품 저장 키를 읽어 자동 변환·덮어쓰기하지 않는다. 실제 영구 프로필 증표는 쓰지 않는다.
2. 생성/진행 테스트: 1,000 seeds×5장, DAG 모든 경로 최소/최대7전투, 보스 우회/고아/순환 없음, 정예0·서비스0 경로, XP10/장. 실제 그래프·해시·버전·경로·보상/RNG 상태를 저장하며 seed만 재생성하지 않는다.
3. 거래/저장 테스트: 승리 XP/골드/컨디션, 보상·리롤·성장·각성·정산 각각 고유 거래 ID와 멱등 원장. 복제→변경→검증→저장→재읽기 성공 전 공개 상태 교체 금지. 중복 클릭/재접속/저장 실패/충돌/알 수 없는 버전/변조 그래프/부적격 각성은 거부하고 이전 유효 상태 보존. 전투 재개는 전투 전 체크포인트로 재시도하며 RNG·보상 재추첨 금지.
4. 행동 테스트: 각 역할의 1차/2차/3차 비교, 모든 훈련 경로, 동일 시드 재현, 타깃 사망·시전자 사망·중복 이벤트·동률 ID·행동 점유·컨디션 단일 적용·완화상한·궁극 보류/소비. 발동횟수뿐 아니라 유효량과 무발동 사유를 기록한다.
5. 캠페인 통합 검증 전제: 무열쇠/무궁극/비전설, 서비스회복0/예비0, 출전6 고정과 상한6→9, 지원병 유무, 모집·훈련 실지출·전투불능을 구분한다. 모든 승리 산술 모델과 실제 전투 시뮬레이션을 별도로 보고한다. 플레이시간·모바일 조작·중단/재개는 실제 UI 단계에서 측정한다. 실패를 통과로 완화하지 않는다.
6. 제품 통합은 이후 별도 단계다. 구 0.9 진행 저장은 원래 지도/보상/전투/2장 종료/정산으로 끝낸다. 구2장 완주를 새5장 완주로 기록하지 않는다. 새 출정 경계에서만 검증된 새 프로필 표현을 만들며 기존 증표·해금·정산 원장과 안전 백업 보존. 저장 전환 상세는 save-version-transition.md를 따른다.
7. 복구: 테스트 실패면 P0 모듈 연결을 중단하고 검증 로그/실험 저장은 보존한다. 구 runner 및 기존 저장을 그대로 사용한다. 새 저장을 구 포맷으로 다운캐스트하거나 두 진행을 합치지 않는다. 손상된 새 저장이 있다고 오래된 키를 조용히 최신 상태처럼 쓰지 않는다. 운영 통합·공개 배포는 별도 승인/검증 전까지 하지 않는다.
