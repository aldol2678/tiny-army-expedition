## 1. 공통 실행 모델

### 1.1 시간·자원·결정 순서

고정 STEP의 정수 tick만 판정에 쓴다. 초→tick은 기존 ticksFor를 사용한다. 상태에는 battleId, rulesVersion, profileId, unitId, actionSeq, actionId, targetIds, commitTick, resolveTick, recoveryUntil, cooldownUntil, paidMana, remainingBudget, subeventIndex, ultimateState를 저장한다. 대상 ID는 런타임 배열 인덱스가 아닌 해당 전투의 안정된 ID다.

한 틱의 권장 순서:
1. 만료 상태 제거 → 생존/출전/시작 연결 갱신 → 마나 재생.
2. 이미 확정한 행동의 해결 이벤트를 `(resolveTick, sourceId, actionSeq, subeventIndex)` 오름차순으로 처리. 앞 이벤트로 사망한 유닛은 뒤 행동을 취소한다. 사망과 치유가 동시라는 별도 부활 예외는 없다.
3. 공개 예고/현재 HP/위치로 스냅샷 작성 → 비점유 반응/연결 계산 → 각 병사 행동 후보 선정.
4. 병사 ID 오름차순으로 각자 최대 1개 점유 행동 확정. 실제 대상·자원은 확정 직전에 재검증. 새로운 행동의 해결은 최소 다음 틱이다. 같은 틱 반복 발동 금지.

행동 상태: ready → windup → resolve → recovery → ready. 시작 전 합법 대상 없음은 대기이며 비용 0. commit은 대상 재검증 후 쿨다운·마나·예산·궁극권을 원자적으로 차감하는 순간이다. commit 후 사망/이탈/전투 종료는 아래 예외 외에 환불하지 않는다. resolve에서 재선정 허용 기술도 1회만, 같은 범위와 우선순위로 수행한다. 무효면 fizzle. 실패 횟수로 재시전 루프를 만들지 않는다.

- 점유 행동 중 평타·새 주문·새 치유·자발 이동 금지. 수동 지휘는 병사 행동을 취소하지 않고 기존 별도 체계를 유지한다.
- 자동 공격의 기존 남은 시간이 사라지지 않는다. 점유 종료까지 공격 가능 시각을 밀고, 미래 예산을 빌린 경우 그 시간 부채도 더한다. 쿨다운 자체는 흐르지만 준비된 행동을 여러 번 적립하지 않는다.
- 정상 치유와 보호 연결은 기존 역할을 유지하되 새 행동을 추가할 때 병행 무료 출력을 만들지 않는다. 평타 간격은 공격속도 적용 후 값 A, 정상 치유 간격은 supportPeriodCostFactor까지 반영한 H다.
- 신규 비마나 기술은 mana=0. 신규 기술 재사용은 병사 CDR 최대 15% 및 해당 비용 계수를 한 번 적용한다. 지휘 CDR은 적용하지 않는다. HP 임계치 비교는 ratio <= threshold, 현행 군의관 응급 배율만 원래 `< .35`를 유지한다.
- 모든 초기 지연은 최소 해당 준비 시간. 신규 긴 주기 기술은 개막 즉시 난사하지 않는다. 준비/후딜은 공격속도·CDR로 줄이지 않는다(P0). 이동은 이동속도/둔화 영향을 받는다.
- 시전자 전투불능: 연결·자가 엄호·미지급 보호·미해결 공격·장판 취소. 이미 지급된 보호막은 원래 만료까지 유지. 예비는 발동/충전/연결 불가. 전투 끝에 남은 예산을 다음 전투로 옮기지 않는다.

### 1.2 공통 대상 함수

거리 경계는 현행처럼 range+.01 이내. 원 안 판정도 같은 epsilon을 쓰며 검증 fixture에 고정한다. 시작 슬롯 자격은 이동 후에도 재계산하지 않는다.

- E(공격): 합법 지휘 집중 대상 → 거리 오름차순 → ID 오름차순.
- V(고가치): 합법 지휘 집중 대상 → 공개 예고 공격 중인 적 → 현재 HP 내림차순 → 거리 → ID. 조준 확정 후 새 집중 명령도 이미 잠긴 표적을 바꾸지 않는다.
- H(치유): 살아 있고 결손 HP>epsilon → HP 비율 오름차순 → 실제 결손 내림차순 → 거리 → ID.
- P(보호): 살아 있고 이번 지급량보다 기존 보호 잔량이 작은 아군 → 공개 예고의 남은 시간 오름차순(없음=∞) → HP 비율 → 기존 보호 잔량 → 거리 → ID.
- 지면 후보: 범위 내 적의 현재 위치를 후보점으로 삼고 적격 수 내림차순 → 중심 적까지 거리 → 중심 적 ID. 위치는 commit에 고정한다. 보이지 않는 미래 적 경로/난수 예지는 금지한다.
- 모든 랜덤 치명은 기존 seeded RNG만 쓴다. 비치명 행동은 치명 RNG를 소모하지 않는다. 불러오기/배열 순서 변경으로 tie-break가 달라지면 실패다.

### 1.3 이벤트·유물 계약

모든 이벤트에 rootActionId, eventId, parentEventId, unitId, family, skillId, phase, actionType, effectKind, damageType, canCrit, enhancedBasic, sourceKind, paidCast, ultimateModifier를 남긴다. `(actionId, subeventIndex)` 중복은 무시한다. 궁극 modifier를 붙여도 원래 actionType을 갈아 끼우지 않는다.

- 기본/강화 평타: basic_attack, physical(마법사 일반 평타만 magic), enhancedBasic 여부. 강화탄·일제 사격은 canCrit=false. 적격 기본공격 유물 한 번만 적용.
- 주문: unit_skill/magic/paidCast=true는 commit 한 건이며 마나 지출 기록이다. 성공한 유료 주문의 집계는 별도 paidSpellSuccess 이벤트다. **현행 성공 시전 계승을 위한 P0 제안:** 직접 주문은 resolve 시 합법 대상에게 피해 해결을 한 번 시도한 경우(보호막 완전 흡수도 성공), 지면 주문은 합법 위치에 설치가 완료된 경우에만 성공 카운터 +1. 준비 중 취소/시전자 사망/모든 대상 무효인 fizzle은 마나는 잃지만 성공 카운터·환급은 0이다. 신규 windup의 취소 의미를 명시한 것이며 현행 즉시 주문에 이미 취소 단계가 있다고 주장하지 않는다. 잔향 수정은 성공 카운터가 3의 배수가 되는 **resolve 종료 직후**, 해당 actionId에 기록된 실제 지불액 기준 한 번 환급한다. 최대 50%, 최대 마나 초과분 폐기. 시전자가 그 시점에 사망했으면 환급하지 않고 이후 소급도 하지 않는다. 성공/환급 처리 여부를 snapshot에 각각 저장하여 불러오기·다중 대상 resolve로 중복하지 않는다. 잔불 틱·둔화·궁극 압축은 paidCast=false, sourceKind=derived이며 성공 카운터도 추가하지 않는다.
- 정상 진료: actionType=heal, sourceKind=normal, tag=normal_heal. 실제 회복>0일 때만 정상 치유/응급 붕대함 발동. 집중 수술은 special_heal, 궁극 분배도 special_heal. 정상 치유 보너스·진료 시계·응급 붕대함을 수술에 자동 적용하지 않는다.
- 보호막: shield/shield/none, 치유 아님. 보호 태세: unit_skill/protection/none, 보호막 아님. 연결: passive_protection. 보호·이동·조준에는 피해/처치/치명 이벤트 없음.
- AP/ATK/컨디션은 기존 projectUnit 경로에서 한 번 계산. 훈련과 유물은 family/기존 branch/시작 슬롯 자격 유지. 지휘 유물은 궁극/병사 기술로 전이하지 않는다.

## 2. 공통 상한·예산·중첩

기존 안전 상한 유지: HP/ATK/AP 양의 증가 +50%, DEF 비율 +50%, 유물 평면 DEF +40, 연결 DEF +20; 기본 피해/정상 치유/보호막/마법 고유 피해 각 +35%; 최종 피해 감소 55%; 공속 +50%, 이속 +25%, 마나 재생 +50%; 병사 CDR 15%, 지휘 CDR 20%; 치명 50%/2.5배, 환급 50%. 초과량을 다른 능력치·궁극 게이지·보호막으로 전환하지 않는다.

피해 감소 태세는 DEF/연결/지휘 방어 계산 뒤, 보호막 앞에 적용한다. incoming을 D, 기존 완화 후 피해를 X라 하면 새 방어가 줄일 수 있는 양은 `min(remainingProtectionBudget, X*rate, max(0,X-.45*D))`이다. 즉 DEF가 이미 55% 상한이면 추가 방어 0. 보호막 흡수는 현행처럼 그 뒤의 별도 자원이며 무적이 아니다. 0량 완화는 유효 피격을 소비하지 않되 창은 연장하지 않는다. 동시에 같은 보호 태세는 실효 완화량 최대 1개, 동률 sourceId 최소만 소비한다.

보호막은 기존보다 **엄격히 큰 잔량**만 교체한다. 덧셈·동일량 만료 갱신 금지. 교체 시 이전 잔량은 expired로 기록, 새 지급량만 신규 예산에서 차감한다. 작은 잔량을 큰 보호막으로 합쳐 이득을 만들지 않는다. 모든 치유는 실제 결손까지; 남는 치유/탄/대상 슬롯/장판 틱은 폐기한다. 상한만 지켰다고 균형 합격이 아니다. 대상수·시전 횟수·공격 정지·피해/치유 시점도 검증한다.

## 3. 8개 2차의 두 기술

아래 수치는 P0 시험용. `C`는 컨디션 배율, `AP`는 투영 AP. 기존 계수·주기·사거리는 훈련/유물 투영 후 값이다. 평범한 자동 공격은 어느 직업에서도 아래 두 칸에 포함되지 않는다.

### 3.1 성채수호병

1. **방벽 연결 / guardian_link (계승)**
   - 시작 슬롯 상하좌우 출전 아군 중 방벽 계열을 제외. 시전자 생존 동안 유지. 이동 거리와 무관하며 전맵 신규 대상 추가 없음.
   - `min(20, AP*기존 연결 계수)` DEF. 여러 연결은 가장 큰 1개, 동률 sourceId. mana/CD/행동 점유 0. 전투불능 즉시 다음 생존 연결 후보로 교체.
   - 연결 운용 계수 .60→.70/.80, 방벽 특화의 본인 DEF 유지. passive_protection이며 정상 보호막 유물 대상 아님.
2. **방벽 전개 / bastion_guard (신규)**
   - 연결 가능한 아군 중 공개 피해 예고가 1초 이내 또는 HP<=50%이며 적이 근접 위협 거리 150 이내일 때. P 순서에서 예고/HP 조건 충족자 1명. 실제 현재 연결의 수혜자가 다른 방벽에서 보호받는 중이면 후보 제외(P0).
   - 준비 .2초/후딜 .4초, CD 10초/초기 3초, mana 0. 평타 정지. 1.5초 동안 첫 유효 피해에 rate=.15, 총 완화 예산 `AP*C*.5`를 적용하고 종료.
   - resolve에 합법 연결 대상이 아니면 P로 한 번 재선정. 시전자 사망/연결 상실로 남은 태세 종료, 환불 없음. unit_skill/protection, 치유·shield 아님. 추가 AP 계수에 연결 훈련을 재적용하지 않는다.
   - 우선순위: 연결 갱신(비점유) → 방벽 전개 → 평타/이동.
   - 카드: “이웃을 잇고, 위험한 한 번을 막습니다.” / “연결 대상만 보호 · 중첩 불가”.

### 3.2 돌파선봉병

1. **돌격 / charge (계승)**
   - CD 준비 + 적이 투영 돌격 사거리 이내. E 1명 위치를 commit에 고정. 기존 반경 내 살아 있는 적에 기존 ATK/AP 계수 물리 피해. 비치명. 현재 구현과 같이 실제 이동·넉백·기절 없음.

### 3.4 기동연사수

   - 카드: “평소엔 진료, 위급할 땐 시간을 들여 수술합니다.” / “수술 중 다른 행동 중단 · 생존자만 치료”.

   - 기존 보호 사거리 내 P 대상 존재, 기존 8초 CD/2초 초기 지연, mana 0. 준비 .2초/후딜 .3초. 기존 투영 보호량을 S라고 하면 **총 예산 2S**, 지급 1회 S씩 2회(기존 2대상 총량 유지).
   - 첫 지급 resolve, 두 번째는 .8초 뒤. 둘 사이 다른 점유 행동은 가능하되 두 번째 지급은 첫 행동의 예약 효과이며 새 시전/쿨다운/유물 발동이 아니다. 지급 대상은 서로 다른 ID, 두 번째 때 P 재선정. 기존 보호 잔량>=S면 후보 제외.
   - 두 번째 합법 대상 없음/시전자 사망이면 S 폐기. 첫 대상 보호막이 소진돼도 두 번째 몫을 다시 주지 않는다. 각 보호막 지속은 실제 지급부터 기존 4/4.5/5초, 같은 양 반복 만료 갱신 금지.
   - 특화 S 계수 1/1.25/1.50, 운용 지속 유지, shieldBonus 한 번. 교체 손실/미지급/만료/실제 흡수를 별도 기록.
   - 우선순위: 예약 지급 처리 → 예고 1초 이내 대상에게 방벽 → 정상 진료 → 방벽 → 평타. 정상 치유를 계속 굶기지 않는다.
   - 카드: “가볍게 치료하고, 두 번에 나눠 보호합니다.” / “보호 총량 유지 · 두 번째 대상 재선정”.

## 4. 4개 궁극 계열: 준비·결합·소모 계약

### 공통 P0와 권장 입력

**권장: 두 기본 기술 자동 + 조건형 자동 궁극.** PC 1/2와 모바일 지휘 버튼 2개를 그대로 지휘 전용으로 둔다. 궁극을 1/2에 겹치거나 세 번째 필수 입력을 만들지 않는다. 각성 병사 카드에 “궁극 준비 중 / 조건 대기 / 사용 완료” 읽기 전용 표시와 보류 사유를 제공한다. 접근성은 색 외 아이콘/문구로 전달. 이는 선택 권고이지 사용자 확정이 아니다.

P0: 해당 출전 각성 병사에게 전투당 1회, 전투 경과 5초 뒤 준비. 처치/피격 충전 없음, 예비는 충전 없음. 한 원정 각성 1명은 기존 비교안 전제이며 확정 아님. 상태 locked→charging→armed→consumed. armed에는 별도 시간 초과 없음; 조건 없으면 기본 기술은 정상 사용하고 궁극은 보류. 적격 기본 기술 commit과 같은 원자적 거래에서 사용권 소모. 이미 진행 중인 행동에 사후 부착 불가. 사망/전투 종료 시 남은 권리 폐기, 다음 전투 1회로 초기화. 기본 CD/마나/행동 부채 초기화 금지. 궁극 자체 paidCast/event 피해는 없고 연결 행동에 ultimateModifier+ultimateActionId를 붙인다.

대안(모두 미확정):
- 수동 예약 1버튼: 모바일 별도 궁극 버튼, PC 별도 키(예: U, **후보 키**)로 armed 상태만 예약. 1/2 유지. 준비 중 재누름은 해제 가능하되 commit 뒤 취소/환불 불가. 같은 대상/비용/예산이라 자동보다 무료 출력을 얻지 않는다. 타이밍 재미 대 조작 부담/기기 간 숙련 격차를 비교해야 한다.
- 자동/수동 토글: 접근성 선택 폭은 늘지만 설정·예외·튜토리얼이 늘어난다. P0에 동시 채택하지 않는다.
- 행동 충전 반복 궁극: 장기전 재미 대신 공속/병과별 충전 편향·자원 관리 증가. 별도 예산 검증 전 보류.

### 4.1 불굴의 선봉 / iron_oath

- 수성형: 방벽 전개 후보의 공개 예고가 1초 이내면 결합. 기존 선택된 연결 아군 1명만. 단발 예산 `AP*C*.5`를 그대로 두고 유효 타격 최대 3회/창 2초에 나눠 사용(rate .15 유지). 총 예산·55% 상한 동일. 적격 피격 수/예산/창 중 먼저 소진되면 종료. 추가 연결·피해 전가·전군 무적 없음. 기본 전개 CD/준비/후딜 유지. 시전자 사망/연결 상실 즉시 남은 예산 폐기. 낮은 HP만으로 일반 전개는 가능하지만 궁극은 보류한다.
- 돌파형: 돌격 대상 반경 내 적>=2 또는 공개 예고 중인 표적 존재일 때 결합. 준비 .45→.20초로 압축, 차이 .25초를 후딜에 추가하여 총 점유시간 보존. 기존 돌격 피해/표적 수·운용 DEF 원인 1회. 엄호 반응 창은 해결 시부터 기존 1.2초, 추가 보호량 없음. 헛돌격이면 궁극 소모, 엄호 생성 없음.
- 카드: “전열이 버틸 순간을 앞당깁니다.” / 수성 “같은 보호를 여러 타격에” / 돌파 “빠른 준비, 긴 복귀”.

### 4.2 천공의 명수 / eagle_signet

- 일점형: 조준 잠금이 살아 있고 대상이 공개 예고 중이거나 현재 HP>=강화탄 투영 피해일 때 다음 강화탄에 결합. 기존 강화탄 + **다음 일반 평타 1회 분량**만 앞당긴다. 각각 기존 기본공격 보너스 1회, 합친 한 비치명 피해 이벤트로 해결. 이후 공격 가능 시각에 A 추가, 공격 카운터는 현재 강화탄 1회만 증가하며 빌린 몫은 다음 카운터를 진행시키지 않는다. 이는 미래 일반탄의 피해 예산만 당기고 강화탄 빈도는 늘리지 않는 의도적 정책이다. 예: commit 전 attacks=2 → 궁극 강화탄 후3 → A 추가 부채를 포함한 대기 후 일반탄4 → 일반탄5 → 강화탄6. 빌린 몫을 별도 attacks=4 사격으로 다시 생성하지 않는다. 재대상은 기본 강화탄 규칙; 미래 평타 부채는 빗나가도 지불. 준비/사거리/조준 비용 유지. 단기전 종료로 부채 미지급 이득을 반드시 별도 기록한다.
- 탄막형: 일제 사격의 원래 발동 조건을 충족하고 서로 다른 합법 적>=3이면 결합. 궁극의 추가 사거리 0(일제의 +30만 유지), 해당 범위 안 대상 상한을 `기존 maxTargets+2`까지 확대. 원래 주 표적 몫은 유지하고 **기존 보조 총 예산을 추가 대상에 균등 분배**. 대상 부족 몫은 폐기; 주 표적에게 넘기지 않는다. 기존 A/후딜/비치명 유지, 추가 공격 묶음 없음. 훈련 maxTargets와 보조 배율은 분배 전 원 예산에 1회 반영.
- 카드: “정해진 화력을 필요한 곳에 모읍니다.” / 일점 “다음 한 발을 당겨 사용” / 탄막 “같은 탄막을 더 넓게 분배”.

### 4.3 비전의 현자 / arcane_seed

- 홍련형: 본인 잔불이 살아 있고 잔여 틱>=2, 다음 폭염 주 표적이 그 영역 안이며 정상 마나/CD/행동 요건 충족 시 결합. 폭염 자체는 기존 비용·주기·피해 유지. commit에 해당 장판 잔여 피해 원장을 잠그고 이후 틱 취소, resolve에 잔여 예산을 원래 장판 영역 현재 적 최대 3명에 균등 분배. 빈 영역/초과 피해 폐기. 원래 장판 snapshot 보너스 사용, 압축에 새 AP/비전 렌즈/마법 보너스 재곱 없음. 압축은 dot/derived/noncrit/paidCast=false, 잔향 카운트 추가 없음. 시전자 사망 시 폭염과 잔여 압축 취소, 환불 없음.
- 조합 실행성: 잔불 설치 후보에 `max(폭염 ready, 잔불 회복 종료, 마나 충족 시각)+폭염 준비 < 잔불 종료-1초`가 참인 경우에만 궁극용 예약 표시. 기본 마나40/재생3/폭염28/잔불12라면 마나40에서 폭염 직후 잔불을 무조건 쓸 수 없다는 점을 UI에 숨기지 않는다. 필요한 마나가 모일 때까지 일반 평타를 유지하고, 불가능한 조합 때문에 일반 폭염을 무기한 보류하지 않는다. 일반 기술 우선이며 궁극은 다음 합법 기회를 기다린다.
- 한파형: 서로 다른 접근 적>=2, 다음 경계에 결합. 중심/방향은 가장 가까운 접근 적→가까운 아군 벡터로 정하고 맵에 클립한 폭50×길이150 회랑. 면적 약7,500으로 기본 원 면적 약7,854 이하. 총 대상 3/개별 둔화1.25초/강도25%(보스12.5%)/지대4초 동일. 제어 총 예산을 늘리지 않고 모양만 바꾼다. 동시 진입은 기본 tie-break, 피해·빙결 없음.
- 카드: “주문의 시간과 자리를 한 번 바꿉니다.” / 홍련 “남은 잔불을 지금 소모” / 한파 “같은 냉기를 긴 길목으로”.

### 4.4 생명의 수호자 / covenant_lamp

- 구명형: 수술 합법 대상 있고 치유 범위 내 HP<=50% 생존 부상자>=2일 때 결합. 원래 수술 총량 T=`AP*C*1.5`, H 순서 최대 2명에 각 T/2를 예약. resolve 때 기존 후보 무효라면 아직 예약하지 않은 H 대상 1회 재선정. 부족분/0치유는 폐기, 남는 몫을 다른 대상에 재분배하지 않는다. 대상이 1명뿐이면 일반 단일 수술 사용하며 궁극은 보류한다(P0, 단일 집중형은 대안). 정상 치유 배율/유물 제외, 특화 진료 지속 유지. 수술 준비·후딜·정상 진료 지연·CD 동일, 궁극은 원인 1개/파생 치유 최대2개.
- 방호형: 교대 방벽 commit 시 서로 다른 P 대상 2명 모두 공개 예고 1초 이내이면 결합. 기존 2S 예산/S 2회 유지; 두 번째 지급을 .8초 뒤 대신 첫 지급 다음 tick으로 앞당긴다. 첫/두 번째 대상 재선정·기존 보호 비교는 원래 규칙. 이미 지급한 보호막을 회수/이전하지 않으며 미지급 분만 시점을 바꾼다. 각자의 기존 지속은 지급 시부터, 총 보호량·CD 변화 없음. 두 번째 대상 무효/사망이면 해당 S 폐기, 궁극 환불 없음.
- 카드: “새 힘을 더하지 않고 구조 시점을 바꿉니다.” / 구명 “한 수술을 두 부상자에게” / 방호 “두 보호막을 빠르게 전달”.

### 밸런스 및 완주 검증 게이트

- 동일 seed/편성/훈련/유물/비용으로 1차 기준, 2차, 3차를 비교한다. 자동 기술 2개를 얻었다고 DPS/HPS가 자동 2배가 되는 결과는 거부하고 신규 예산·행동 점유부터 수정한다.
- 짧은 일반전/이동하는 적/다수 잔병/단일 보스/긴 마나전/후퇴 불가/동시 부상 각각 비교. 두 기술 중 하나가 거의 무발동이면 기술 이름만 채운 것으로 판정한다.
- 궁극0/열쇠0/전설0으로 일반5장 완주 후보를 따로 검증. 특정 병과 보유 체크/전용 면역 해제/궁극 필수 보스는 추가하지 않는다. 3장 유물→4장 궁극 체험→5장 활용 순서 유지.
- 필수 로그: skillId별 candidate/commit/resolve/fizzle, 대기 이유, 첫 유효 발동 tick, targets, actionLockTicks, borrowedAttackTicks, unpaidDebtAtEnd, manaSpent/refunded, 원/잔여/폐기 예산, 실제 HP 피해/회복, 초과 피해/치유, 보호 실흡수/교체손실/만료, 제어시간, relicProc root ID, ultimateUse/holdReason.
- 4·5장 유물 기여가 3차에서 사라지지 않아야 한다. 정상 치유 빈도 급감·훈련 운용 경로 무가치·궁극 한 명이 나머지 군단을 대체하면 계수보다 조건/빈도/예산부터 조정한다.

## 6. 남은 결정

P0를 바로 제품에 적용하지 않는다. 먼저 공유 행동 잠금이 현행 전투 체감에 주는 영향, 연사 일제의 실제 이점, 후퇴 경로 비용, 홍련 조합 실행 가능성, 정상 진료 유물 기여를 프로토타입에서 확인한다. 자동 궁극/전투당1회/5초 준비/가칭/2차 자격 통합은 사용자 확정으로 기록하지 않는다. 본 문서는 기존 브랜치를 변경하거나 신규 필수 병과를 만드는 승인이 아니다.
