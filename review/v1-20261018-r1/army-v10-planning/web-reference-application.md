# 웹 오토배틀러 레퍼런스 → 부대 1.0 적용안

검토일: 2026-10-18. 범위: 공식 소개와 공개 이미지 확인, 우리 게임에 맞춘 설계 제안. 게임 구현 변경은 하지 않았다.

## 1. 결론과 적용 경계

우선순위는 **① 압축된 부대 목록 ② 역할이 읽히는 병사 카드 ③ 배치·교대 효과 미리보기 ④ 구매 후보/출전/예비의 명확한 분리 ⑤ 전투 결과의 원인 피드백**이다. 새 관리 시스템을 추가하기보다 지금 있는 선택을 이해하기 쉽게 만든다.

- 현재 설계의 보유 20명, 출전 6→9명, 배치 12칸을 출발점으로 삼는다. 레퍼런스의 인원 제한을 그대로 옮기지 않는다.
- 예비는 다음 적에 맞춰 교대할 병력이다. 예비 전체의 자동 버프, 파견·지원 직책, 새 자원은 추가하지 않는다.
- 5장 원정과 2차 고유 기술 2개, 3차의 기존 2개+궁극기 1개를 보존한다. 카드 공간 부족을 이유로 확정 기능을 삭제하지 않는다.
- 아래 숫자와 화면 구성은 구현 제안이며, 구현·기기 테스트 완료를 뜻하지 않는다. 기존 설계의 상세 규칙은 [콘텐츠 계획](content-plan.md), [전직·기술](class-skill-progression.md), [5장 원정](five-chapter-run.md)을 따른다.
- 어사이드가 수행한 실행·평가를 이번 조사에서 직접 수행한 것으로 취급하지 않았다. 이번에는 실제 원정 플레이, 계정 생성, 구매, 게임 다운로드를 하지 않았다.

## 2. 확인한 근거

### A. Auto Necrochess: 배치 규칙과 작은 단위의 선택

[공식 itch.io 페이지](https://stopsignal.itch.io/auto-necrochess)는 마우스 중심 조작, 리롤, 전투 시작/일시정지, 판매, 동결, 합성을 설명한다. 책은 행의 오른쪽에 있어야 작동한다는 위치 조건도 명시되어 있다.

공식 본문에 실린 준비 화면 이미지에서 왼쪽 상품 패널, 오른쪽 여러 행의 병력 배치, 선택 유닛의 짧은 설명과 작은 수치를 확인했다. 이미지는 정적 자료이므로 반응 속도·실제 터치 동작·전투 템포까지 검증하지 않았다. 직접 이미지 URL은 서명 오류가 났으나 원문에 삽입된 이미지는 확인했다.

**우리에게 가져올 것:** 선택한 병사의 역할과 작동 조건을 짧게 보여주는 정보 밀도. **가져오지 않을 것:** 같은 병사 합성 규칙, 동일 색감·삽화·화면 배치, 더블클릭만으로 중요한 상태를 바꾸는 방식.

### B. Dwarves: Glory, Death and Loot: 소수 병력의 역할과 비교

[공식 웹 데모](https://ichbinhamma.itch.io/dwarves-glory-death-and-loot-demo)는 최대 10명 규모의 개인화된 부대와 자동전투를 소개한다. [공식 Steam 설명](https://store.steampowered.com/app/2205850/Dwarves_Glory_Death_and_Loot/)은 장비·역할·진형 준비와 적 구성에 따른 대응을 강조한다.

Steam 공개 갤러리의 Forge 화면에서 슬롯형 장비 목록, 선택 장비의 상세 설명, 속성별 변화량 표시를 확인했다. 이는 현재 상용판 홍보 이미지이며 웹 데모와 동일한 UI·규칙이라고 단정하지 않는다. 모든 장비 변경이나 전투를 직접 실행한 것은 아니다.

**우리에게 가져올 것:** 다음 적에 맞춰 교대할 이유, 선택 전후의 구체적인 변화량. **가져오지 않을 것:** 개인 장비 슬롯 대량 도입, 많은 재료 재화, 상용판의 영구 능력 강화 구조.

### C. Backpack Battles: 위치의 가치를 눈으로 보여주기

[공식 데모](https://playwithfurcifer.itch.io/backpack-battles)와 [공식 프레스킷](https://playwithfurcifer.github.io/backpack-battles-presskit/)은 구매뿐 아니라 배치가 빌드를 바꾼다고 설명한다.

**우리에게 가져올 것:** 위치·인접 관계를 이해시키는 시각 언어와 영역 구분. **가져오지 않을 것:** 가방 테트리스, 아이템 제작 트리, 상대 플레이어 매칭, 원본 삽화·가구형 상점 레이아웃.

## 4. 하나의 준비 흐름으로 묶기

1. **다음 적 확인:** 이미 공개되는 적 정보에서 전열 압박/후열 위협 등 관찰 가능한 특징을 짧게 표시한다. 아직 알 수 없는 정보나 승패를 확정적으로 예언하지 않는다.
2. **현재 부대 확인:** 출전 수/상한, 예비 수, 활성 시너지, 목표 유물 진행을 한곳에서 읽는다. 조건 미충족 유물을 자동 활성으로 보이게 하지 않는다.
3. **교대 후보 선택:** 예비 카드를 누르면 기존 출전 카드와 같은 형식의 상세가 열린다. 컨디션과 역할 공백을 비교한다.
4. **배치 제안 확인:** 새 칸 또는 교대 대상을 선택하면 보호 연결, 시너지 문턱, 관련 유물의 활성/비활성이 바뀌는 것만 보여준다. 피해 기대값이나 승률을 계산했다고 주장하지 않는다.
5. **적용 또는 취소:** 미리보기는 보유·골드·배치·난수·세이브를 바꾸지 않는다. 적용 한 번으로 합법 배치만 확정하며 취소 시 원상태를 유지한다.
6. **전투에서 확인:** 중요한 기술 발동을 읽고, 결과에서 실제 발동한 사건을 다시 확인한다. 수치가 없는 곳에 ‘최고 기여자’ 같은 추정 순위를 붙이지 않는다.

결과 예시 문구는 실제 전투 기록이 있을 때만 채운다: ‘방벽병의 보호 연결: 대상 2명’, ‘군의관 회복: 유효 회복량 N’. ‘패배 원인: 힐러 부족’처럼 검증하지 않은 인과를 단정하지 않는다.

## 5. 미리보기 구현 계약

- 실전과 별개 공식을 복제하지 않는다. 동일한 순수 계산 경로로 현재 편성과 후보 편성의 효과를 구하고 차이만 렌더링한다.
- 출전 인원 상한과 격자 빈칸 수는 별개다. 빈칸이 있어도 출전 한도를 넘으면 적용을 막고 이유를 표시한다.
- 보호는 정확한 시작 격자 인접 조건을 따른다. 대각선이나 화면상 가까워 보인다는 이유로 적용하지 않는다.
- 예비는 출전 시너지·전투 유물·궁극 발동에 포함하지 않는다. 목표 유물 검색의 보유 병과 인식은 별도 규칙이다.
- 1차/2차/3차 표시가 바뀌어도 병사 ID·컨디션·부모 병과·훈련 계승이 깨지지 않아야 한다.
- 해제되는 효과도 획득 효과와 같은 중요도로 보여준다. 색에만 의존하지 않고 ‘획득/해제’ 텍스트와 선 형태를 다르게 쓴다.
- 정보 패널을 열거나 닫고 미리보기만 취소한 행동은 저장 상태와 다음 보상을 바꾸지 않는다.

## 6. 접근성·모바일의 불확실성과 검증안

공식 페이지의 HTML5·마우스·터치 표기는 실제 기기 적합성의 보증이 아니다. 이번 검토는 데스크톱 클라우드 브라우저의 공개 이미지이며 iOS Safari, Android Chrome, 작은 화면, 키보드 전용, 스크린리더를 테스트하지 않았다.

1.0 최소 검증 제안:

- hover 전용 설명 금지. 탭/클릭으로 상세를 고정하고 명시적인 닫기와 취소를 제공한다.
- 드래그만 강제하지 않는다. ‘병사 선택→칸 선택→적용’ 경로와 키보드 선택/취소 경로를 둔다.
- 터치 대상은 설계 목표 44×44 CSS px 이상으로 시작하되 실제 화면에서 간격·오입력을 검증한다. 이 숫자만으로 접근성 준수를 선언하지 않는다.
- 모바일 세로 화면에서는 전체 화면을 축소하지 않고 목록과 선택 상세를 전환한다. 시너지·출전 상태·적용 버튼은 찾기 쉽게 유지한다.
- 숫자·아이콘·문자를 병행하고 색각 차이에 안전한 구분을 확인한다. 글자 확대 시 겹침, 초점 이동, 최소 두 실제 모바일 환경의 전투 중 복귀·저장을 검사한다.
- 번쩍임·흔들림을 줄일 수 있게 하고 배속 중에도 중요한 기술과 결과 정보가 사라지지 않게 한다. 전투 로그는 자동으로 너무 빠르게 흘려 읽기를 방해하지 않는다.

## 7. 제작 범위와 컷라인

새로 필요한 최소 시각 요소는 역할 아이콘 8개, 출전/예비/미보유 상태 표시, 연결 획득/해제 선, 2차·3차 단계 배지다. 우선 기존 게임의 아이콘·폰트·선·배지를 재사용할 수 있는지 확인한다. 원본 게임의 스프라이트나 프레스킷 자산을 우리 에셋으로 가져오지 않는다.

이번 문서는 에셋 제작 완료 보고가 아니다. 새 대형 배경, 병사별 초상화, 별도 예비 화면, 전투 리플레이는 1.0 최소 구현에 넣지 않는다. 화면은 자체 시각 언어를 유지하고 레퍼런스에서는 **선택을 이해시키는 원리**만 가져온다.

우선 납품 순서: 상태 구분과 역할 카드 → 교대·배치 미리보기 → 주요 전투 사건 피드백 → 실제 기기 검증. 이 순서는 5장·전직 기술 확정 범위를 대체하지 않고 그 범위를 읽을 수 있게 만드는 UI 작업의 순서다.
