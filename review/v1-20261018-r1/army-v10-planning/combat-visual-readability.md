# 전투 애니메이션·보스 연출·가시성 개선안

작성: 2026-10-18 UTC. 상태: 로컬 조사 및 설계 문서. 제품 코드·UI·저장·빌드·배포는 변경하지 않았다. 아래 제작 수치·효과 예산·합격 기준은 시험 후보이며 실제 기기 성능이나 사용자 이해도를 측정한 결과가 아니다.

## 1. 권장 방향

더 많은 빛보다 **누가 준비하고, 어디에 맞고, 언제 끝났는지**부터 보이게 한다.

1. 실제 피해 판정과 접촉 그림의 시간 차이를 먼저 줄인다.
2. 위험 영역의 채움은 바닥, 경계선과 의미 표시는 궁극 효과 위에 둔다.
3. 기존 병과별 자세를 살려 준비·접촉·복귀를 구분한다. 새 그림 때문에 공격 간격을 바꾸지 않는다.
4. 보스는 긴 컷신 대신 준비 화면의 짧은 소개와 전투 중 패턴 순서로 기억시킨다.
5. 신규 패턴은 원/부채 두 문법과 명확한 회복 공백부터 검증한다. 추가 규칙은 별도 승인·규칙 버전으로 구현한다.

현재 1.0 원정 기준은 장당 최소 7전투(보스 포함), 5장 최소 35전투다. 2차 고유 기술 2개, 3차는 같은 2개+궁극 1개이며 지휘 기술 장착 2칸과 다르다. 반복 전투마다 연출 대기를 더하지 않는다. 구 0.9 저장을 새 행동 모델로 바꾸지 않는다.

## 3. 시간과 판정의 두 가지 경로

### A. 우선 적용 후보: 규칙 보존형 표현 수정

- 공격/치유/보호막의 **실제 resolve 순간**에 대상의 접촉 표시·HP/보호 변화가 함께 나타나게 한다.
- 즉시 판정 화살은 긴 비행 대신 발사 방향의 짧은 궤적과 대상 접촉을 동시에 표시한다. 남은 잔상은 사라지는 흔적이며 아직 도착하지 않은 공격처럼 그리지 않는다.
- 원거리 발사체가 길게 날아가는 표현을 반드시 원하면 B 경로가 필요하다. 렌더를 위해 `hit`를 지연하거나 이미 죽은 적을 살려 두지 않는다.
- 기존 준비 힌트는 ‘발사 확정’이 아닌 자세 변화로만 사용한다. 대상이 사라지면 자연스럽게 대기 자세로 복귀하고 헛된 피해/치유 숫자를 만들지 않는다.
- 기존 평타 뒤 복귀 애니메이션은 시각적 잔여 포즈다. 다음 실제 공격이 오면 새 이벤트가 우선하며 공격·이동을 막지 않는다.
- 돌격의 선형 잔상은 이동/충돌 경로가 아니다. 실제 효과는 고정 원형 판정이므로 긴 선을 위험 영역처럼 그리지 않는다.

### B. 별도 승인 대상: 1.0 행동 상태 모델

`skill-implementation-contracts.md`의 ready→windup→resolve→recovery 후보와 연결한다. 이 모델은 준비 중 비용, 사망 취소, 이동/평타 점유, 후딜 등 실제 규칙을 바꾸므로 시각 개선만으로 출시하지 않는다.

렌더는 엔진의 battleId/actionId/sourceId/targetIds/shape/lockedGeometry/commitTick/resolveTick/recoveryUntil/cancelReason을 읽는다. 이는 신규 계약 제안이며 현행 효과에 모든 필드가 존재하지 않는다. 클라이언트 프레임 시간으로 hit 여부나 스킬 준비 완료를 계산하지 않는다. 동일 이벤트 재수신은 중복 재생하지 않는다. 게임 일시정지·숨김 탭·저장 복귀에서 남은 실제 단계로 재구성한다.

판정 피해와 화면 숫자가 일치하려면 event에 actualDamage/absorbed/healed 등 해결된 값을 기록해야 한다. 현재 `effectKind=damage`만으로 실제 피해량을 추측하지 않는다. 치명 가능(`canCrit`)과 실제 치명 발생은 다르므로 실제 crit 결과 없이 치명 연출을 붙이지 않는다.

## 4. 병과별 모션 문법

모든 병사는 발 위치와 실제 좌표를 유지한다. 무기·상체만 작은 범위로 움직인다. 아래 준비/복귀 시간은 엔진 행동이 있는 경우 그 상태 길이에 맞추고, 규칙 보존 경로에서는 시각 포즈만 사용한다. 화면 확대나 점프로 유닛이 다른 판정 위치에 있는 듯 보이지 않게 한다.

| 계열 | 준비 | 접촉 순간 | 복귀/지속 표시 | 피해야 할 오해 |
|---|---|---|---|---|
| 창·방벽/성채수호 | 창을 짧게 당기거나 방패를 수직으로 세운다 | 한 번의 직선 찌르기; 실제 방어 발생은 별도 방패 모서리 표시 | 창 회수, 보호 연결은 얇은 선과 끝점 사각 | 무기 궤적 전체를 광역 피해로 보이지 않게 함 |
| 돌격/돌파선봉 | 몸을 낮추고 무기를 뒤로; 실제 원형 예고 별도 | 고정 원 내부의 한 번 타격, 몸 자체는 좌표 보존 | 어깨 복귀; 실제 자가 방어가 있을 때만 방패 표식 | 순간이동·밀치기·라인 관통을 암시하지 않음 |
| 궁수·저격 | 활 당김; 강화 평타 준비가 확정되는 경우 작은 이중 조준표 | 단일 선형 궤적과 확정 대상 접촉 | 활줄/어깨 복귀 | 저격의 강화 평타를 유료 주문/궁극으로 오표기하지 않음 |
| 연사/기동연사 | 활 위 세 갈래 실루엣 | 실제 targetIds마다 짧은 접촉, 한 root에 묶음 | 활을 내리는 짧은 재정렬 | 3발 그림이 3회 추가 공격/무한 관통을 뜻하지 않음 |
| 화염 | 지팡이 위 각진 불꽃 | 실제 피해 대상에 짧은 불씨 접촉 | 실제 장판만 경계+남은 지속, 장식 잔불은 분리 | 시각 불꽃 밖/안과 실제 피해 범위를 혼동하지 않음 |
| 냉기 | 마름모 결정과 짧은 수직 자세 | 눈송이 대신 명료한 결정 접촉 | 실제 둔화 중에만 작은 시계/결정 표시 | 둔화가 강타 예고까지 늦춘다고 암시하지 않음 |
| 지원·군의 | 손/도구를 목표 쪽으로 들어 올림 | 실제 치유 위치에 + 표식; 피해 표시와 분리 | 팔 복귀, 양은 실제 회복량만 | 만피 대상의 무효 치유를 성공처럼 연출하지 않음 |
| 결계 | 양손 사이 사각/육각 테두리 | 실제 지급 대상의 보호막 외곽 1회 정착 | 남은 보호막은 얇은 분리 표시 | 보호막 부여량을 HP 회복/실제 흡수량으로 합산하지 않음 |
| 보병·잔병 | 보병의 짧은 무기 들기, 잔병의 낮은 몸 | 작고 빠른 1회 접촉 | 발 위치 유지 | 수적으로 많다고 장식 입자를 각자 뿌리지 않음 |
| 강타병·보스 | 무기를 높이 고정하고 실제 예고와 연결 | 전체 화면 대신 범위 안 국소 충격선 | 승인된 회복 상태가 있다면 무기를 내린 고정 자세 | 현행에도 무공격 회복 시간이 있는 것처럼 표시하지 않음 |

기본 4가족(근접/사격/마법/지원)에서 동작을 공유하고 2차는 무기 끝/동작 방향/핵심 표식을 차별화한다. 궁극은 기존 기술의 확대·결합으로 표현하되 실제 판정 밖까지 화면을 덮지 않는다. 상태 확인에 필요한 표식과 미적 잔상을 구분한다.

## 5. 가시성: 무엇을 먼저 읽게 할 것인가

### 레이어 순서(아래→위)

1. 대비 낮은 배경/그림자.
2. 위험 영역의 저불투명 채움, 실제 아군 영역, 얇은 보호 연결.
3. y축 깊이순 병사와 지면 고정 실루엣.
4. 일반 접촉/투사체 잔상/궁극 장식.
5. **실제 위험 경계선·방향·시전자 번호·고정 표시**. 장식은 이 선을 덮지 못한다.
6. 집중 대상/취소/치유·보호 결과 표식.
7. 체력·보호막·마나 및 핵심 상태, 간략 위협 문구. 레이블 겹침은 별도 레이아웃으로 해결한다.

위험 채움 중첩은 최대 alpha 방식으로 제한하고 경계선은 모두 유지한다. 겹침이 많다는 이유로 실제 활성 위험을 숨기지 않는다. 위협 시작 간격 조절은 렌더 최적화가 아니라 조우 규칙 변경이므로 별도 승인·테스트한다.

### 모양·문구 문법

- 적 강타: 닫힌 원+네 방향 충격 눈금+사각 중심, ‘강타’/‘좁은 강타’/‘넓은 강타’.
- 적 일제: 실제 부채꼴+세 방향 화살표, ‘일제 준비’. 직사각형 레이저나 무한 관통으로 바꾸지 않는다.
- 아군 고정 원형 기술: 같은 실제 형상은 유지하되 안쪽 아군 문장과 ‘아군’ 표식으로 적 위험과 구분한다. 색만 다르게 하지 않는다.
- 확정 표적: 고정된 중심/방향 옆 작은 자물쇠+‘고정’. 현재 강타는 생성부터 고정이므로 가짜 추적 단계를 추가하지 않는다.
- 취소: 실제 취소 이벤트에서 선을 즉시 제거하고 짧은 ‘취소’ 표시. 이미 지급된 보호막 등 존속 규칙은 별도로 따른다.
- 타이머는 경계 크기를 변화시키지 않는 숫자/작은 타임바로 표현한다. 실제 게임 초를 쓰며 2배속에서는 ‘게임 시간’과 배속을 함께 식별할 수 있게 한다. 벽시계 시간을 혼용하지 않는다.

경계의 중심선이 판정 경계이며 두꺼운 외곽 장식은 사거리를 늘리지 않는다. 원/부채는 동일 엔진 geometry에서 렌더와 충돌 함수를 만든다. CSS 표시 크기가 작아져도 외곽선 최소 약 2 CSS px, 핵심 문구 12~14 CSS px는 초기 시험 목표다. 캔버스 논리 px를 CSS px로 착각하지 않는다. 좌표 변환/종횡비/zoom에 동일 투영을 사용한다.

### 체력과 숫자

- 기존 안정 ID 체력바 배치·연결선을 유지한다. 체력 위험은 색+느낌표, 보호막은 별도 윤곽/분절, 마나는 별도 줄로 구분한다.
- 체력바를 숨겨 혼잡을 해결하지 않는다. crowded 상황에는 선택 대상 상세와 ‘위험 N명’ 요약을 보조로 제공한다. 누구의 바인지 연결선이 식별되어야 한다.
- 기본 화면은 모든 평타 숫자보다 대상 접촉/HP 변화를 우선한다. 숫자 상세 모드는 별도 선택 후보다.
- 다중 피해 묶음은 `(rootActionId,targetId,effectKind)` 단위가 기본이다. 동일 대상·동일 종류가 짧은 표시 구간 안에 겹치면 합계+타격 횟수로 보여 줄 수 있지만, 서로 다른 적의 피해/치유/흡수/치명을 한 수치로 합치지 않는다.
- 숫자 묶음은 표시만 늦춘다. HP·위험 경고·전투 로그는 실제 resolve에 즉시 반영한다. 결과 패널의 공식 집계를 렌더 합계로 대체하지 않는다.

## 6. 보스 소개와 단계 전환

### 입장

별도 강제 컷신/보스 전 대기 화면을 만들지 않는다. 기존 준비 화면에 보스 이름·실루엣·핵심 패턴 2개·가능한 대응을 통합한다. 첫 조우에서만 0.6~0.9초 이내의 비차단 강조를 시험할 수 있으나 시작 버튼을 막거나 전투 시작 뒤 시간을 훔치지 않는다. 재도전/재방문은 정적 소개로 충분하다. 모션 감소에서는 처음부터 정적이다.

### 다섯 보스의 인상(모두 신규 1.0 후보)

- 1장 파수꾼: 들어 올린 원형 방패→큰 원 강타→쉬는 자세. 원형 문법 한 가지를 학습.
- 2장 문지기: 문짝 방패와 호위 깃발. 강타→호위 부채 일제→공백. 시간 순서가 특징.
- 3장 기록관: 열린 고리 지팡이. 좁은 원→긴 예고 넓은 원→무공격 공백. 작은/큰 범위와 예고 길이를 구별.
- 4장 성주: 갈라진 관과 한쪽 대형 무기. 넓은 강타→호위 사격→보스 공백. 플레이어 궁극이 경고를 가리지 않는지 우선 검증.
- 5장 파수군주: 익숙한 방패+관. 잔병 접근→넓은 원→호위 부채→공백의 유한 순서. 새 장식/새 규칙을 마지막에 쏟지 않는다. 호위 재소환 없음.

1.0 조우 문서의 후보를 시각 언어로 정리한 것이며 현재 보스 5종이 구현됐다는 뜻이 아니다. 장당 7전투 이상에 필요한 패턴 재사용은 적 구성·배치·타이밍 조합으로 하고 보상창이나 컷신을 추가하지 않는다.

### 전환 계약

HP 단계 전환은 현재 구현 사실이 아니며 필수 추가도 아니다. 우선 패턴 순서만으로 차별화한다. 이후 HP 전환을 채택한다면:

- 발동 임계치는 엔진이 한 번만 기록하고, 기존 확정 공격을 몰래 초기화/가속/취소하지 않는다. 권장안은 현재 행동 해결 및 정의된 회복 종료 뒤 다음 순서부터 새 단계를 적용하는 것이다.
- 임계치 도달 시 ‘다음 행동부터 2단계’처럼 보류 상태를 알려 준다. 보스가 먼저 죽으면 전환 연출은 취소한다.
- 카메라 컷·슬로모션·강제 정지·강제 배속 변경·무적·전체 화면 플래시를 추가하지 않는다. 짧은 몸 자세/무기 변화와 상단 상태만 바꾼다.
- 단계 이름 표시는 실제 진행에 종속된다. 기존 타이머는 그대로 흐르고 장식 길이가 공격 가능 시점을 결정하지 않는다.
- 플레이어에게 수동 회피·전투 중 진형 이동·예비 교대를 요구하지 않는다. 준비 배치, 사거리 안 집중, 지휘 수호/회복, 호위 제거가 실제 대응이다.

## 7. 효과 예산과 접근성

초기 제작 예산 후보(기기 실측 전):

- 필수 정보는 무제한으로 버리라는 뜻이 아니라 **생략 불가**다. 실제 활성 경계/고정 표시/HP/지휘 상태를 모두 유지한다. 밀집은 조우 설계와 레이아웃에서 해결한다.
- 장식 동시 입자는 기본 24개·낮음 0개, 눈에 띄는 국소 궁극 장식은 최대 1개를 시험한다. 두 궁극이 실제 동시 해결되면 두 대상 결과/필수 표식은 모두 표시하고 장식만 단순화한다. 피해 자체를 순차 처리하지 않는다.
- 숫자 풍선은 기본 동시 6묶음 후보. 초과 시 묶거나 상세 로그에 보존하며 HP/피해 이벤트를 폐기하지 않는다.
- 화면 전체 플래시 없음. 카메라 흔들림은 우선 미도입; 나중에 넣어도 기본 꺼짐·독립 옵션·모션 감소에서 강제 꺼짐, 판정/입력 좌표는 바꾸지 않는다.
- reduced motion: 이동 바운스/돌림/확장 파동/카메라 줌/흔들림/숫자 부유를 끈다. 고정 자세 2~3개, 정적 경계, 상태 이름, 실제 남은 시간과 접촉 표식은 유지한다. 효과를 모두 없애 정보가 사라지는 모드는 금지한다.
- 소리 꺼짐에서도 동일하게 이해되어야 한다. 시각과 같은 이벤트를 사용한 준비/접촉 소리는 보조다. 다수 동시 소리는 우선순위/쿨다운으로 제한하되 플레이 규칙에 영향 없음.
- 화면 읽기용 의미 상태는 ‘새 강타 예고’, ‘범위 고정’, ‘취소’, ‘단계 변경’ 등에서만 요약한다. 매 프레임 숫자를 읽거나 모든 평타로 알림을 쏟지 않는다.
- 접근성 판단은 흑백 확인만으로 완료 선언하지 않는다. 작은 화면·색각 차이·모션 민감 사용자 관찰이 필요하다.

## 8. 실행 순서와 검증 게이트

### P0: 규칙 보존 표현 프로토타입

시작 승인 후 별도 브랜치에서 접촉 타이밍, 위험 경계 상단 레이어, 단순 타이머, 병과 실루엣 강화만 한다. 배포는 별도 승인이다.

비교의 핵심은 동일 seed/roster/inputLog에서 HP·사망 tick·공격 수·자원·targetIds·최종 결과가 변경 전후 동일함이다. 렌더가 RNG/쿨다운/좌표를 쓰지 않는 것도 검사한다. 이 문서에서는 테스트를 실행하거나 통과했다고 주장하지 않는다.

### P1: 원형/부채 패턴과 보스 순서

새 행동 모델 승인 후 geometry/timing 계약을 구현·시험한다. 패턴 다양화는 기존 렌더 패치와 분리한다. 신규 원/부채 판정, 시전자 사망 취소, 범위 고정, 회복 공백을 결정론 테스트한다. 2차 기술과 궁극 연출은 그 다음 같은 이벤트에 붙인다.

### 검증 장면

- 320/360/390/430 CSS px 세로, 가로, DPR1/2, 품질 낮음/기본/높음, 1배/2배, 모션 감소/무음.
- 아군 9명+밀집 호위+보스, 원 두 개 중첩, 원+부채 중첩, 경계 화면 끝, 카메라 확대 중 새 경고, 체력바 crowded.
- 적 큰 예고와 아군 궁극 동시, 보호막으로 피해 완전 흡수, 죽는 대상에 이미 해결된 투사체, 시전자 사망 취소, 막타와 단계 임계치 동시, 일시정지/숨김/복귀.
- 모양 경계 안/밖/경계 정확히 위의 점 샘플을 엔진과 비교. 장식 외곽선은 hitbox에 포함하지 않는다. 변환 후 실제 geometry 중심선 오차 1 CSS px 이내를 초기 QA 목표로 삼되 기기별 검증한다.
- 영상에서 실제 resolve와 접촉이 같은 렌더 프레임에 반영되는지 확인한다. 낮은 FPS에서 중간 단계가 생략돼도 공격이 아직 미해결인 것처럼 보이지 않아야 한다.
- 5명 이상 소규모 첫 이해도 시험 제안: 짧게 본 뒤 공격 출처/맞는 영역/다음 단계/지휘 개입 가능 여부를 묻는다. 80% 이상 정답은 초기 게이트 후보일 뿐 검증된 수치가 아니다. ‘회피 버튼을 찾는다’는 응답이 있으면 안내를 수정한다.
- 성능은 대상 기기에서 p95 프레임 시간/드로우 수/장식 수를 기록해 전후 비교한다. 실측 없이 60fps 보장이나 저사양 최적화 완료라고 하지 않는다.
