# 첫 로딩 연출안: 작은 군단의 출정

설계만 작성. 게임 코드·배포·저장 형식은 변경하지 않았다.

## 1. 권장 방향

**작은 깃발 아래 세 병사가 출정을 기다리는 한 장면. 준비되면 곧바로 기존 첫 화면으로 연결한다.**

- 어두운 청록 배경, 작은 크림색 게임 제목, 바닥선 위 창병·궁수·지원병의 단순한 실루엣.
- 화면 문구는 `꼬마 군단 원정대`와 `출정 준비 중` 두 줄이 기본. 버전, 기술 설명, 반복 팁, 큰 카드 테두리는 제외한다.
- 세 병사는 실제 선택 군단이 아니라 장식이다. 병사 등장 수나 이동 거리를 다운로드 진행률처럼 사용하지 않는다.
- 대형 일러스트, 초상화 시트, 영상, 외부 폰트를 로더의 선행 조건으로 삼지 않는다. 처음 받은 HTML 안의 작은 SVG와 CSS만으로 완성한다.
- 완료 후 시작 버튼을 추가하지 않는다. 저장된 진행이 있으면 기존 복원 흐름으로, 없으면 기존 첫 선택 화면으로 들어간다. 로딩 연출 때문에 새 원정을 만들지 않는다.

## 2. 현재 확인한 동작과 제안의 경계

### 현재 코드에서 확인

- `web-support/shell.html` / `shell.css`: 어두운 배경에 크림색 안내 카드. 버전, 제목, 상태, 보조 설명, 실패 시 재시도 버튼이 있다. 병사 애니메이션은 없다.
- `web-support/boot.js`: 모듈 로드 수를 실제 집계한다. 초기화 후에는 초기 초상화의 준비 수를 표시한다. 필수 조건은 게임 UI 초기화와 초기 초상화 준비 완료이며, 이미지의 명시적 대체 상태도 완료로 인정한다.
- 초기 초상화는 궁수·창병·지원병 3종이다. 이미지 로드와 decode를 확인하고 개별 이미지가 12초 안에 준비되지 않으면 대체 처리한다(`resources.js`).
- 준비되면 즉시 로더를 숨기고 앱의 inert를 해제한다. 강제 최소 대기, 가짜 퍼센트, 별도 시작 버튼은 없다.
- 스크립트 실패나 초기 전역 오류는 오류 화면으로 전환한다. 현재 부트 재시도 버튼은 페이지 전체 새로고침이다. 핵심 스크립트에 별도 시간 초과 처리는 없다.
- 게임 내 이미지 실패 안내는 `일부 그림 대체 중`, `다시 받기`, `닫기`다. 각 클릭은 한 번의 요청이지만 사용자는 재시도를 여러 번 누를 수 있다. 페이지 전체에서 한 번으로 제한된 것은 아니다.
- `audio.js`: 배경음악은 새로 열 때 꺼져 있다. 신뢰된 사용자 입력 후 오디오를 활성화하며, 화면이 숨겨지면 정지한다. 효과음 음소거 설정과 배경음악 활성화 상태는 별개다.
- 사용 가능한 장식은 Kenney 기반 배너·금색 테두리·체크 SVG 3개다. 폰트는 Jua, Maple Bold, Pretendard이며 배포 원본 합계 약 4.98 MB다. 로더 표시를 이 파일들에 의존시키지 않는다.

아래 표시 시간, 모션, 문구, 재시도 제한은 **새 제안**이다. 실제 브라우저 성능·시각 검증을 마쳤다는 뜻은 아니다.

## 3. 한 장면의 구성과 표시 시간

### 배치

- 모바일과 PC 모두 중앙의 같은 세로 구성을 쓴다. 콘텐츠 최대 폭 360px, 좌우 여백 최소 20px.
- 위: 게임 제목 24–28px. 가운데: 약 240×120px의 작은 출정 장면. 아래: 상태 14–16px.
- PC에서도 그림을 대형 배경으로 늘리지 않는다. 넓은 여백을 유지한다.
- 안전 영역과 낮은 가로 화면을 고려해 내용은 스크롤 가능하게 한다. 텍스트의 높이를 고정하지 않는다.
- 기본 글꼴은 시스템 한글 글꼴. 게임 폰트가 준비되더라도 이 짧은 화면에서 필수 교체하지 않아 글자 이동을 줄인다.

### 시간 순서

1. 첫 HTML 표시: 배경·제목·정지한 병사·`출정 준비 중`을 바로 보여준다. 스크립트 실행 전에도 읽을 수 있다.
2. 180ms 뒤에도 준비 중이면 병사의 발과 깃발에 작은 움직임을 시작한다. 이 시간은 애니메이션 시작 조건이지 입장 지연 시간이 아니다.
3. 움직임은 발 위치 1–2px, 깃발 기울기 약 3도 안쪽. 1.2초 내외의 느린 주기로 최대 4초만 재생한 뒤 정지한다. 계속 움직이는 로더를 강요하지 않는다.
4. UI와 필수 초기 그림의 준비 또는 대체가 끝나는 순간 기존 게임 화면으로 전환한다. 걸어 나가는 애니메이션의 끝, 음악, 폰트 다운로드를 기다리지 않는다.
5. 아주 빠른 재방문에서는 정지 장면이 잠깐 보이거나 모션 자체가 생략된다. 로고를 보여주려고 추가 시간을 만들지 않는다.

페이지 내부 화면 전환에는 이 전체 로더를 다시 쓰지 않는다. 이후 그림 로딩은 현재 카드의 자리만 유지한다.

## 4. 상태별 문구와 행동

- 기본: `출정 준비 중`. 전체 다운로드를 뜻하는 퍼센트나 가짜 막대는 없다.
- 이미지 단계가 2초 이상 지속될 때만: `군단 그림 준비 중 · 1/3`. 값은 실제 settled 수이며 대체 완료도 포함한다. 모든 게임 자료의 완료율로 설명하지 않는다.
- 8초 이상: `조금 더 걸리고 있어요`. 상태 문구를 교체하되 설명을 계속 늘리지 않는다. 불필요한 재시도를 자동 시작하지 않는다.
- 이미지 실패 또는 12초 시간 초과: 기본 실루엣과 병과 이름으로 진행한다. 이미지 때문에 게임 전체를 오류 화면으로 막지 않는다.
- 핵심 코드 실패: `게임을 불러오지 못했어요`와 `다시 시도` 버튼. 코드를 불러오지 못한 상태에서 `계속하기`를 보여주지 않는다.
- 핵심 코드가 20초 넘게 미확정이면: `연결이 지연되고 있어요`와 안전하게 가능한 재시도만 표시한다. 시간 경과만으로 확정 실패라고 단정하지 않으며, 늦게 정상 완료되면 정상 진입한다.
- JavaScript 사용 불가: `게임을 실행하려면 JavaScript를 켜 주세요`. 동작하지 않는 재시도 버튼이나 영구 애니메이션은 숨긴다.

초기 방문 여부를 저장하려고 새 저장 키를 만들지 않는다. 첫 방문·재방문은 같은 로더를 사용하고, 기존 저장 복원 결과를 확인하기 전에는 `이어서 하기`나 진행 내용이 있는 문구를 추측하지 않는다.

## 5. 재시도와 진행 보존

### 그림

- 한 부트 세션에서 실패한 같은 그림은 사용자의 `그림 다시 받기` 요청으로 **추가 한 번만** 요청한다. 자동 무한 재시도는 금지한다.
- 그 시도도 실패하면 버튼 대신 `기본 그림 사용 중`을 표시한다. 병과 이름과 실제 플레이 정보는 텍스트로 항상 남긴다.
- 원본이 없어도 정지 실루엣과 텍스트가 남는다. 로더 자체 SVG가 표시되지 않아도 제목·상태·오류 버튼은 HTML 텍스트로 작동한다.

### 게임 코드

- 현재의 무조건 전체 새로고침을 그대로 재사용하지 않는다. 초기화와 플레이 진행의 시작 여부, 저장 실패 여부를 먼저 구분해야 한다.
- 아직 게임 상태가 생성되지 않은 초기 부트 실패는 사용자 요청으로 한 번 재시도할 수 있다. 페이지 새로고침을 쓰면 재시도 표식은 캠페인과 분리된 세션 범위에서 관리한다. 재시도 실패 화면에는 반복 버튼 대신 연결 확인 안내를 둔다.
- UI 또는 캠페인이 일부라도 생성된 뒤에는 기존 인스턴스를 중복 생성하거나 새 원정을 시작하지 않는다. 입력과 시뮬레이션을 부트 완료 전까지 진행시키지 않는 계약이 필요하다. 현재의 inert만으로 모든 시뮬레이션 정지를 보장한다고 가정하지 않는다.
- 메모리에 저장되지 않은 변경이 있거나 상태가 불명확하면 자동 새로고침·저장 삭제·기본값 덮어쓰기는 하지 않는다. 기존 인스턴스를 유지하고, 이용 가능한 기존 백업 기능으로 안전한 복구 경로를 마련한 후 재시도를 허용한다.
- 이 설계는 저장 보존을 구현했다고 주장하지 않는다. 구현 시 기존 저장 보호 동작 및 부분 초기화 실패 경로 검증이 선행되어야 한다. `진행은 안전해요` 같은 미검증 보장은 화면에 쓰지 않는다.

## 6. 소리와 선택형 시작 화면

권장안은 **로딩 중 무음**이다. 효과음과 음악을 시작하기 위한 클릭을 로더에서 억지로 받지 않는다.

- 첫 입력은 브라우저 오디오 활성화 조건일 뿐, 음악 재생 동의로 취급하지 않는다.
- 게임 진입 후 사용자가 배경음악을 켰을 때만 기존 야영지 음악을 재생한다. 음악 준비는 게임 시작을 막지 않는다.
- 소리가 꺼져 있어도 장면의 의미와 상태는 완전히 전달된다. 경고음, 출정 팡파르, 진입 순간 큰 볼륨 변화는 넣지 않는다.

짧은 대안: 추후 타이틀 화면이 꼭 필요하면 **부트 완료 뒤 별도 화면**으로 둔다. `출정` 또는 확인된 저장이 있는 경우 `이어서` 버튼, 기본 꺼짐인 `음악` 토글만 배치한다. 음악을 켠 뒤에만 잔잔한 야영지 루프를 사용한다. 첫 로딩 시간을 늘리고 클릭을 추가하므로 이번 권장안에는 포함하지 않는다.

## 7. 접근성과 성능 기준

- reduced-motion에서는 모션과 전환을 제거한다. 빛 번쩍임, 화면 흔들림, 파티클 폭발은 없다.
- 상태 영역 하나만 role=status / aria-live=polite로 쓴다. 초당 애니메이션 갱신이나 반복 카운트를 읽지 않으며 단계 변경만 알린다. 장식 SVG는 aria-hidden이다.
- 재시도 버튼은 최소 48px 높이, 키보드 포커스가 명확해야 한다. 오류 표시와 정상 진입 때 포커스가 숨겨진 로더에 남지 않게 이동한다.
- 320px 폭, 가로 화면, 200% 확대 및 400% 확대에 해당하는 재배치에서 잘림·가로 스크롤·버튼 겹침이 없어야 한다. 사용자 확대를 막지 않는다.
- 일반 텍스트 대비 4.5:1 이상. forced-colors에서도 문구와 버튼 경계가 남아야 한다.
- 로더 전용 CSS+SVG 목표는 압축 전 10KB 이내, 추가 네트워크 요청 0건. 기존 외부 UI SVG도 로더의 필수 리소스로 쓰지 않는다.

## 8. 구현 전 확인 목록

- 캐시가 빠른 첫 진입/재방문에서 인위적인 대기가 없는가?
- 느린 네트워크에서 본문·폰트·그림보다 로더 텍스트가 먼저 보이는가?
- 세 초기 그림의 ready/fallback 조합마다 정확하게 진입하는가?
- 그림의 재시도 실패 후 텍스트만으로도 플레이할 수 있는가?
- 핵심 스크립트 누락, 늦은 도착, 부분 UI 초기화 실패 때 이중 부트가 없는가?
- 저장 복원 성공, 저장 손상, 저장 거부, 메모리 전용 진행에서 덮어쓰기나 진행 소실이 없는가?
- 화면 숨김, reduced-motion, 확대, 키보드, 화면낭독기에서 정상인가?
- 로딩 중·첫 클릭 때 의도하지 않은 음악이 나오지 않는가?

### 확인한 소스

`tiny-army-sites/web-support/shell.html`, `shell.css`, `boot.js`, `resources.js`, `audio.js`, `ui-assets/README.md`, `fonts/provenance.json`. 저장 보호 관련 주의는 `tiny-army-sites/dist/js/campaign.js`의 저장·복원 분기를 추가 확인해 작성했다. 이 문서는 로컬 소스 검토 기반이며 실기기 검증 결과가 아니다.
