# 1.0 지도·성장 시점·컨디션 독립 검증

2026-10-18 UTC. 판정: **구조 PASS / 피로 민감도 WARN / 실제 전투 밸런스 UNKNOWN**.

## 바로 활용할 결론

1. 실제 격리 JS 생성기 1,200개 시드 × 5장, 6,000개 지도에서 346,557개 **장별** 경로를 전수 열거했다. 전 경로 정확히 7전투·10XP이며 보스 우회, 강제 서비스 통과가 없다. 장간 연결은 캠페인의 순차 전이로 35전투·50XP이다. 346,557개를 5장 완주 플레이 횟수로 표현하지 않는다.
2. 1,200개 원정 중 102개(8.5%)는 휴식 노드가 아예 없다. 6,000장 중 3,624장(60.4%)도 휴식 없음. ‘휴식을 했어야 통과하는 보스’로 난이도를 맞추면 시드가 빌드를 잠근다. 휴식은 추가 여유로 취급해야 한다.
3. 시험값에서 무휴식·일반전 경로·전투불능0·고정6명은 최종 컨디션55. 처음부터12명 보유, 역할을 무시하고 컨디션 높은 순으로 교대하면 최종 최저95. 모집 비용·성장 분산 없이 12명을 공짜로 둔 상한 비교이므로 현실적 완주 증명은 아니지만 **예비 +6의 영향이 크다**는 신호다. 피로를 조절하기 전에 실제 획득 인원과 역할별 대체 가능성을 붙여야 한다.
4. 3장 보스 후 열쇠 기회 및 4장 입구 각성 기회는 21전 후, 남은 전투14회다. 끝나고 처음 해금되는 궁극 문제는 구조상 피했다. 하지만 열쇠 지급과 각성 효과는 아직 어댑터 미구현이고 현재 실행 코드는 모두 ‘건너뛰기’만 된다. 1.0 완성 직업으로 표기하면 안 된다.

## 재현

프로젝트 루트에서 `node army-v10-validation/routes-condition/validate.mjs`.

- 읽은 정본: `army-v10-implementation/src/{graph,campaign,config}.js`, `army-v10-planning/IMPLEMENTATION-BASELINE.md`.
- 산출물: `results.json`, `test-results.txt`, 이 보고서, `validate.mjs`.
- 원본 코드·문서·운영 저장·운영 앱 수정 없음. 결과 JSON에 읽은 파일 SHA-256 포함.
- 그래프는 1,200개 시드 전수 경로 열거 + 자체 validateGraph 재검증. 캠페인 타이밍은 실제 transition API로 별도 35전투 가정 승리 1회 진행. 캠페인 1,200회 전체 저장 회귀라고 주장하지 않는다.

## 구조 검사

- 6,000지도 전부 7전투/10XP, 서비스0 경로 및 정예0 경로 존재.
- 각 서비스의 모든 출구에 대해 직전 전투에서 같은 출구로 직행하는 간선 존재. 방문 강제나 합류 휴식 강제 없음.
- 지도상 휴식 개수는 원정당 0~8개가 관측됨. 생성 노드 수이며 한 경로에서 전부 방문 가능하다는 뜻은 아니다.
- 한 장에서 정예 최대6회 경로가 실제 존재. ‘장당 정예2회’는 비교 시나리오이지 생성 상한이 아니다. 위험/보상 표시에 이를 반영해야 한다.
- 최종35전 뒤 성장 보상 없음. 실제 보상 게이트34회, 마지막은 정산 경계만 남는다.
- 보상2/5/8 뒤 성장 기회에서 남은 전투33/30/27회. 열쇠21 뒤14회, 각성21 뒤14회.
- 새 군단 유물3회안의 6/15/27은 문서 명세이며 현재 캠페인의 실행 후보 제시기로 연결되어 있지 않다. 연결할 경우 남은 전투29/20/8회라 마지막 선택도 사용 기회는 있다.

## 컨디션 비교

전투승리 소모 일반1/정예2/보스3, 전투불능 추가4, 시작 시 예비였던 병사 +6, 휴식 전원+20, 상한100/하한0. 출전 정원은 전투 **전** XP 기준6→7→8→9. 로스터6명은 항상 전원 출전, 로스터9/12명은 높은 컨디션 우선 교대한다. 모두 시작100이며 미구현 회복 어댑터 대신 검증용 산술 모델에서만 계산한다.

다음은 ‘마지막 전투 후 보유 병사의 최저 컨디션’ 중앙값이며, 괄호는 시드 최소~최대다.

| 경로 정책 | 보유6 / 전투불능0 | 보유9 / 전투불능0 | 보유12 / 전투불능0 |
|---|---:|---:|---:|
| 정예0·휴식0 |55 (55~55)|58 (58~58)|95 (95~95)|
| 휴식 우선 |79 (55~95)|79 (57~95)|95 (93~95)|
| 정예 최대·휴식0 |42 (32~50)|46 (38~54)|94 (92~95)|

휴식 우선은 해당 장의 전체 경로를 미리 보고 휴식 수 최대, 동률이면 피로 최소를 고르는 낙관 정책이다. 실제 플레이어의 선택·화면 정보·상점 포기 비용을 재현하지 않는다. 일부 시드에서 휴식을 찾아 정예를 밟아 최저 컨디션이 오히려 나빠질 수도 있으므로 ‘휴식 개수 최대’가 최적 전략이라는 의미도 아니다.

### 전투불능 민감도

보스마다 가장 낮은 컨디션 출전 병사1명만 전투불능이 된다고 가정:

| 경로 정책 | 보유6 | 보유9 | 보유12 |
|---|---:|---:|---:|
| 정예0·휴식0 |35|42|91|
| 휴식 우선 |65 (35~91)|65 (41~91)|91 (89~91)|
| 정예 최대·휴식0 |22 (12~30)|30 (22~38)|89 (85~91)|

추가 스트레스군은 매 전투 가장 낮은 컨디션 출전자1명 또는2명이 전투불능이 되는 경우다. 정예0·휴식0에서도 로스터6/9의 최저 컨디션은0이 된다. 로스터12는 각각90/86이다. **같은 취약 인물에게 전투불능이 집중되는 극단적 가정**이며 실제 전투불능률, 사망률, 패배율이 아니다. KO가 발생했어도 전투는 전부 승리했다고 입력했다.

6명 무휴식·KO0 장말은91/82/73/64/55, 5장 보스 직전58로 설계 산술과 일치한다. 컨디션 효율식0.70+0.003×C에서 직전58은87.4%이다. 큰 예비대의 무손실 회복 때문에 이 차이는 전투 엔진 연결 후 역할별 피해·보호·회복 지표와 함께 봐야 한다.

## 후속 검증 순서

1. 실제 모집 시점·20G 지출·훈련 투자·배치 역할을 반영해 로스터6/9/12 비교를 다시 수행. 12명 무료 시작 모델을 출시 판정에 사용하지 않는다.
2. 서비스/보상/각성 어댑터의 멱등 결산을 구현한 뒤 ‘휴식 없음·궁극 없음·예비 없음’ 경로를 실제 조우로 실행한다.
3. 보스5종을 컨디션100만으로 튜닝하지 말고 정상 무휴식 진입58 및 보스 KO 누적군으로 비교. 특정 지원병·휴식·다수 예비대가 필수 답이 되는지 확인한다.
4. 예비 +6을 바로 하향하거나 휴식을 강제 생성하는 패치는 아직 하지 않는다. 현재는 원인 신호만 있고 실제 승률·영입 경제·교대 손실 데이터가 없다.

총36개 정책×로스터×KO 시나리오, 각1,200시드의 **가정 피로 계산**이다. 43,200회 실제 전투 또는 완주 테스트가 아니다. 반복 결정성과 산술은 확인했지만 재미·시간·모바일 UI·지원병 스킬·조우 공략·저장 이전·생산 환경은 검증 범위 밖이다.
